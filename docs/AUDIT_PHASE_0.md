## 4. What does not exist yet (explicitly, so nobody pretends otherwise)

- No database, no migrations, no models.
- No auth, no users, no roles, no sessions.
- No AI provider integration of any kind — **no mock is shipped either**, so no
  code path can pretend to generate video.
- No projects, jobs, videos, storage, credits, billing, notifications, admin.
- No WebSocket, no worker, no queue.
- No CI, no Docker, no deploy, no monitoring.

## 5. Risks and blockers for the next stages

| Risk | Severity | Mitigation |
|---|---|---|
| No Postgres locally → Stage 3 cannot be verified as written | high | install `postgresql` in Termux **or** provision a dev DB and document it |
| No Docker → Stage 12 verification impossible on-device | high | document a GitHub Actions + hosted deploy path, or install Docker via proot |
| No AI provider credentials → Stage 7 "real integration" cannot be proven | high | user supplies a key; until then only a clearly-labelled dev mock |
| Python 3.14 is ahead of some libraries | medium | pin versions; verify each new dependency has a wheel **before** designing around it |
| Phone RAM limits load testing | medium | run load tests from another machine against the dev server |
| Secrets handling | medium | `.env` git-ignored, `.env.example` only, no keys in source |

## 6. Restructure plan (order of work)

1. Keep the current skeleton, extend it — do not rewrite.
2. Database + migrations (Postgres) → contract tests.
3. API layer on top of repositories/services, resource-level authorization.
4. Auth (Argon2id + short-lived access token + rotating refresh).
5. Provider abstraction with a capability registry; a dev mock labelled as such;
   real provider only with credentials.
6. Jobs + WebSocket with DB as source of truth.
7. Credits with an append-only ledger and idempotency keys.
8. Frontend screens against the real API, AR/EN + RTL.
9. Performance measurement, then optimize what the numbers show.
10. Tests → CI → deploy → runbook.

## 7. Priorities

P0: DB schema + auth + resource ownership (everything else depends on it).
P1: provider integration + job lifecycle + WebSocket recovery.
P2: billing correctness and idempotency.
P3: performance, deploy, observability.
