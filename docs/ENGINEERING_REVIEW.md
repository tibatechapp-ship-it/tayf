# التقييم الهندسي العلمي — Tayf Studio v0.4.0

> تاريخ التقييم: 2026-10-31 · النطاق: التطبيق كاملًا (الخلفية، الواجهة، البنية، النشر، الوثائق)
> المنهجية: كل درجة أدناه مسنَدة إلى دليل قابل للتحقق (اختبار يجري، كود يُقرأ، بناء ينجح) — لا درجات انطباعية.

---

## 1) المنهجية

قُيِّم المنتج على سبعة أبعاد هندسية، ولكل بُعد درجة من 10 مسنَدة إلى دليل:
تشغيل مجموعة الاختبارات فعليًا (`pytest` — 99 اختبارًا)، بناء الواجهة فعليًا
(`tsc --noEmit && vite build`)، تشغيل حي للخدمة وفحص الاستجابات ترويسةً بترويسة،
وقراءة الكود المصدر طبقةً طبقة، إضافة إلى مسح تنافسي للمنصات المغلقة والمفتوحة.

## 3) المسح التنافسي

### 3.1 المنصات المغلقة (السحابية)

| المنصة | الموضع الأساسي | ما تتفوق به | ما ينقصها مقابل طيف |
|---|---|---|---|
| Runway (Gen-4) | لقطات توليدية سينمائية | جودة الفيديو التوليدي، أدوات تحرير إطار | لا رصيد قابل للتدقيق/استضافة ذاتية/شفافية مصدر |
| Sora / Veo | توليد مشاهد طويلة واقعية | أعلى واقعية بصرية | مغلقة تمامًا، لا API ذاتي الاستضافة |
| Pika / Kling | محتوى اجتماعي قصير | سرعة وانتشار | تحكم مؤسسي ضعيف، تسعير اشتراك |
| Synthesia / HeyGen | أواتار متحدث | صوت/وجه بشري واقعي | لا لوحة قصصية مشاهدية، عربي محدود الجودة |
| InVideo / Fliki / Pictory | قوالب تسويقية سريعة | مكتبات قوالب ونص→فيديو جاهز | مخرجات قالبية، لا ملكية للبنية |

(مقارنات القطاع: pixflow.net — «Best AI Video Generators»، وقارنات 2026 للأسعار.)

### 3.2 المشاريع المفتوحة المصدر

| المشروع | نوعه | الحد العملي |
|---|---|---|
| LTX-Video / LTX-2.5 | نموذج توليد فيديو محلي | أوزان ثقيلة جدًا (بحساب FuturPulse ≈ 200.9GB للأوزان المنشورة) ويحتاج GPU A100-class عمليًا |
| Open-Sora / CogVideoX / HunyuanVideo | نماذج توليد مفتوحة | أبحاث/تجارب — ليست منصة جاهزة بمستخدم نهائي |
| MoneyPrinterTurbo / ShortGPT | سلاسل إنتاج نص→فيديو | أقرب منافس فئويًا — لكن بدون حسابات/رصيد/عزل مشاريع/أمان محتوى مؤسسي |
| Frametell / huashu-motion | مولدات شرائح وموشن | شرائح تعليمية/تسويقية لا لقطات توليدية |

### 3.3 موضع طيف على الخريطة

طيف يقع في **فئة شبه فارغة**: منصة كاملة (حساب + رصيد + مشاريع + مهام + تخزين + أمان محتوى) **عربية أولًا**، **ذاتية الاستضافة خفيفة حتى على Termux/هاتف**، **بشفافية إجبارية** (وسم المحاكاة ورد الرصيد). أقرب المنافسين إما سحابة مغلقة بلا سيطرة على البيانات، أو مكتبات بدون منصة. هذه هي الفجوة التي يجب التوسع منها لا ملاحقتها.

## 4) الفجوات مرتبة بالأولوية

### P0 — قبل أي إطلاق عام (جودة/ثقة)
1. **تعليق صوتي عربي (TTS)** — أكبر فجوة إدراكية للمنتج العربي.
2. **طابور مهام مستقل** (Redis + RQ/arq) — فصل التوليد عن عملية الـ API ليتحمل حملًا متوازيًا.
3. **تحديد معدل الطلبات + رموز تحديث + استرجاع كلمة مرور**.
4. **مراقبة أساسية**: `/metrics` (Prometheus) + إبلاغ أخطاء.

### P1 — التمايز التنافسي
5. معاينة مشهد قبل التنفيذ + إعادة توليد مشهد واحد بدل المهمة كلها.
6. قوالب مشاريع جاهزة (إعلان، شرح، تريلر) بموجهات عربية مضبوطة.
7. تصدير SRT/ترجمة ومشاركة روابط مؤقتة موقعة.
8. مزود فيديو حقيقي إضافي (API خارجي متى توفّر مفتاح) بجانب zai_gateway.

### P2 — التوسع
9. تعاون فريق (أدوار على المشروع) + سجل نشاط.
10. خط زمني تحريري في الواجهة (سحب/ترتيب مشاهد).
11. PWA + إشعارات اكتمال المهام.

## 5) خطة 90 يومًا قابلة للقياس

| الأسبوع | المخرج | معيار القبول |
|---|---|---|
| 1–2 | TTS عربي عبر مزود قابل للتبديل | مهمة تُنتج MP4 بصوت عربي + اختبار تكامل |

| 9–12 | معاينة + إعادة توليد مشهد + قوالب | تعديل مشهد واحد لا يكلف إعادة كل المشاهد |

## 6) الخلاصة

المنتج يجتاز اختبار «هل هذا هندسة إنتاجية أم نموذج أولي؟» من الجهة الهندسية:
اختبارات حقيقية، هجرات مزدوجة الاتجاه، عزل ملكية، أمان محتوى، وشفافية لا يوفرها
كثير من اللاعبين التجاريين. التفوق على «الكبار» لا يتحقق بملاحقة جودة نماذجهم
(سباق رأس مال حاسوبي) بل بتعميق الفئة التي يملكونها هم أصلًا: **منصة عربية
شفافة خفيفة الاستضافة مع سلسلة قيمة كاملة من الموجه إلى MP4 بفاتورة رصيد
قابلة للتدقيق** — ثم سد P0 (الصوت العربي، الطابور، المراقبة) لتحويل القاعدة
المتينة إلى منتج مؤسسي جاهز.
